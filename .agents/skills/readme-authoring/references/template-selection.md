# Template selection and substitution

| Template | Choose when |
| --- | --- |
| [Balanced root](../assets/balanced-root.md) | A root README needs purpose, status, onboarding, and documentation routes |
| [Documentation gateway](../assets/documentation-gateway.md) | Maintained guides already provide detail and the README should route readers |
| [Module or subsystem](../assets/module-subsystem.md) | A directory needs local scope, contracts, integration, and ownership boundaries |
| [Example or workflow](../assets/example-workflow.md) | A bounded runnable path needs inputs, invocation, outputs, and resource context |
| [Research or benchmark](../assets/research-benchmark.md) | Method, reproducibility, results provenance, and scientific limits are central |

## Required handling

Templates are output scaffolds, not project facts. Uppercase `{{SUBSTITUTION_FIELDS}}` and author comments identify work to complete. They are intentionally present in the template assets; remove or replace them in an authored README. Do not publish a made-up value to fill a field.

Required reader information may be expressed in prose, an example, a table, or a precise link to maintained documentation. Optional sections should be omitted when they do not help the requested task. There is no mandatory word count, section order, badge budget, or visual inventory.

Verify links from the final destination, not from the template asset directory. Commands shown as prose substitution fields are not runnable examples. Add fenced commands only after checking real definitions. Reconcile new content with existing accurate material rather than copying a template over the file.

## Narrow updates

Do not open a template for a single typo or link correction unless it resolves a real structural question. Templates are appropriate for creation and substantial restructuring, not a requirement to restyle every edit.

## Tips

Preserve the primary reader journey. A gateway still needs a meaningful purpose and starting path. A research README still needs a usable route to inputs and method. A balanced root can use branding, alerts, and diagrams without becoming a showcase page.
