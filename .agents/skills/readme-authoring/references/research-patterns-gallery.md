# Research patterns and example gallery

## Evidence boundaries

The [study report](../../../../docs/research/github-readmes-2026-10-30/REPORT.md), [catalog](../../../../docs/research/github-readmes-2026-10-30/CATALOG.md), and [metrics](../../../../docs/research/github-readmes-2026-10-30/METRICS.md) cover 56 established projects and 58 separate showcase nominees, collected on 2026-10-30. The sample is purposive, not representative of all GitHub. Source indicators are heuristic; four rendered headers were spot-checked. It is not a ranked beauty audit or a causal adoption study.

The useful distinction is between documentation/contribution gateways and more self-contained illustrated onboarding. Do not turn observed frequencies into mandatory badge counts, layouts, or emoji rules. Historical nominations and current READMEs can differ.

The [Awesome README showcase](https://github.com/matiassingers/awesome-readme) supplies nominations, not a universal standard. [GitHub's README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes), [Standard README](https://github.com/RichardLitt/standard-readme/blob/main/spec.md), and [Best README Template](https://github.com/othneildrew/Best-README-Template) provide additional reference structures with different authority and scope.

All links above come from existing collected material. Do not fetch them automatically. Inspect current content only when browsing is allowed and the task actually needs it; otherwise use the recorded observations and state their date. Borrow a useful pattern, not another project's identity or unsupported claims.
