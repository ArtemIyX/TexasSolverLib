# Images, banners, and demonstrations

## Choose the asset's job

| Job | Useful asset |
| --- | --- |
| Identity | Compact logo or informative banner |
| Explain an application | Current screenshot showing a recognizable task |
| Explain a CLI interaction | Short readable terminal recording plus text commands |
| Show scientific output | Labeled result with method/context link |
| Explain a transformation | Before/after pair or flow illustration |

## Required

Use existing, authorized assets or create assets only when the task includes that work. Do not invent screenshots of capabilities or show illustrative artwork as measured output. Preserve attribution and usage rights. Do not hotlink a third-party logo as if it were TexasSolver branding.

Resolve local asset paths from the target README. Choose descriptive alt text for informative images; decorative images should not repeat a paragraph of unrelated keywords. Keep essential steps and claims in text. Mark illustrative or historical output when it might otherwise be mistaken for current results.

## Tips

Crop to useful content, keep terminal text readable, and avoid oversized recordings. Check transparent logos and diagrams against both themes when rendering is available. A `<picture>` element can select a theme-specific asset; both sources must be real. GitHub theme fragments are another supported pattern, not a reason to duplicate irrelevant graphics.

## Avoid

Large embedded headings that become unreadable on narrow screens; unexplained stock images; animated installation commands without a text equivalent; stale UI captures; invented graphs to decorate performance claims.

[Sniffnet](https://github.com/GyulyVGC/sniffnet#readme) demonstrates coordinated product imagery. [HTTPie](https://github.com/httpie/cli#readme) demonstrates terminal behavior. Use the relevant lesson rather than copying their assets.
