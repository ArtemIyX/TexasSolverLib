# Maintenance and review

## Completion checks

- Inspect only the scoped diff and necessary supporting material; preserve unrelated changes.
- Confirm changed statements against their actual evidence and intended reader.
- Check local documents/assets from the edited README's directory, including exact case.
- Inspect headings, renamed anchors, balanced code fences, alerts, and details blocks.
- Check commands against definitions and distinguish examples from observed output.
- Remove unfilled template substitutions and unused scaffolding from an authored README.
- Preserve license, attribution, scope boundaries, and relevant limitations.

## Report validation honestly

| Performed check | Appropriate statement |
| --- | --- |
| Source inspection | Commands/claims checked against named definitions |
| Local link resolution | Referenced local files exist |
| Rendered inspection | Named layouts/formatting inspected in specified renderer/theme |
| Execution | Exact command, scope, and actual result |

Do not imply execution from command review, rendering from fence checks, or external availability from a locally recorded URL. Builds, tests, documentation generation, benchmarks, installs, and solver jobs require the applicable authorization. Simple README corrections do not need new application tests.

## Review findings

Report a concrete defect, location, impact, and supported correction. Examples include a missing target document, an optional dependency presented as mandatory, a command naming an unregistered target, or an unsupported scientific promise. Distinguish preferences from defects and return no findings when the selected content is sound.

## Maintenance triggers

Recheck affected README content when public targets, option defaults, dependencies, workflow arguments, status evidence, documentation locations, or licenses change. Do not refresh every screenshot or re-audit the entire repository for a one-line request.

Apply the project log skill after completed edits. Review-only work must not mutate the reviewed README; record any requested log update separately and within authorization.
