# Scope and workflow

## Required

Identify the target README, requested change, intended reader, and mode. Inspect the current file before choosing a template. A repository README, module README, and experiment README have different responsibilities.

For changed claims, keep a compact working evidence map: claim, authoritative file or source, and what it actually establishes. This map need not become a deliverable. Use targeted searches rather than reading every project document.

For an update, preserve unrelated text and formatting. For a restructure, inventory useful content before moving it. Do not silently discard limitations, dependency attribution, supported workflows, or research provenance to shorten the page. Creating a linked companion document is appropriate when authorized by the requested restructuring scope; otherwise suggest the split.

Review mode produces findings and, when requested, suggested wording or patch text; it does not apply edits without authorization. Distinguish a factual defect or broken route from a subjective preference. A stylistic rewrite is not necessary merely because a different template exists.

## Useful procedure

1. Inspect the target, applicable repository instructions, and evidence for affected claims.
2. Choose the smallest relevant subset of references.
3. Write or review for the primary reader journey.
4. Inspect the scoped result using [maintenance and review](maintenance-review.md).

## Example

Request: repair one technical-report link. Check the existing target and the actual document title; correct that link only. Do not add a banner, reorganize the README, or change project maturity wording.

Do not treat README authoring as permission to change code, build configuration, publication settings, or dependency versions. Use specialized project skills only when the authorized task genuinely includes their domain.
